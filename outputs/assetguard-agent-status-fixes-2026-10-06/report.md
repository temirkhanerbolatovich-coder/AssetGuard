# AssetGuard: согласованная свежесть и состояния подключения Agent

Дата: 2026-10-06. Реализация после просмотра действующего сайта. Основа checkout — `dca5a86`, предыдущая production application — `f4f56e7`. Исправление опубликовано и принято на production в application `7c45435` 2026-10-06 19:07:22 UTC. [Приёмка публикации](../assetguard-agent-status-publication-2026-10-07.md).

## Подтверждённые проблемы

- Кабинет считал сохранённый `ONLINE` свежим независимо от возраста отчёта. Административная сводка уже считала просроченные отчёты `STALE` по серверному порогу.
- Обзор объединял компьютеры без подключённого Agent, ожидание первого snapshot и просроченные отчёты в `UNCHECKED`. Отсутствие Agent превращалось в предупреждение о свежести.
- Исходная XML-версия `GLPI-Agent_v1.20` сравнивалась буквально с `1.20` и получала ложное предупреждение `UNSUPPORTED`.

## Исправление

Сервер добавляет `connection_status` рядом с сохранённым `status` в endpoint summaries, карточках endpoint/asset и workspace кабинета. Общая функция в существующем модуле endpoints сохраняет приоритет `IDENTITY_CONFLICT`/`OFFLINE`, затем вычисляет `STALE` по `ASSETGUARD_ENDPOINT_STALE_AFTER_HOURS`; равенство порогу ещё не считается просрочкой. GET не вызывает maintenance, не меняет статус, updated_at или историю. SQL-сводка operations использует ту же политику; регрессия сравнивает ответы напрямую.

Frontend использует серверный результат в обзоре, реестре, кабинете и администрировании. Старый backend без `connection_status` поддерживается прежним клиентским расчётом. «Нет свежих данных» включает `STALE`/`OFFLINE`; Desktop/Laptop без endpoint получают «Agent не подключён», endpoint без snapshot — «Ожидается первый отчёт». Отдельные ссылки открывают соответствующие фильтры реестра. Ручной учёт остальных типов имущества сохраняется. Явный конфликт, OFFLINE и списание имеют приоритет; свежий `REQUIRES_VERIFICATION` остаётся задачей проверки.

Сравнение версии допускает только точное представление `1.19`/`1.20` либо известный префикс `GLPI-Agent_v` перед ними. Raw evidence и `latest_inventory.source_version` остаются неизменными. Неизвестные/patch-версии, произвольные префиксы и суффиксы остаются неподдержанными. Порог, поддержанные релизы, tenant/location scope, endpoint identity и принятие baseline не ослаблены.

Миграций, зависимостей и новых архитектурных слоёв нет. Обработка, модель и хранение Vision не менялись. Подсказка для просроченного Agent указывает фактическое задание `AssetGuardInventory`.

## Проверка

- Фокусированный unit/integration прогон: **27 passed**. Проверены порог 7 часов и его граница, специальные статусы, совместимые/неизвестные версии, согласованность пяти типов ответов и operations, четыре роли, отсутствие чужого endpoint и изменений БД/истории.
- Новый Chromium E2E: **1 passed**. Синтетический набор: свежий и просроченный компьютер в одном кабинете, компьютер без Agent, endpoint до первого snapshot и мебель. Проверены счётчик 1, отдельные фильтры, кабинет «1 из 2» и общий значок «Требует внимания», подписи связи, отсутствие ложного предупреждения о версии и отсутствие горизонтального overflow при 390/320 px.
- Полный прогон `ASSETGUARD_RUN_BROWSER_E2E=1 python -m pytest -q --tb=short` из backend: **170 passed in 125.79s** (148 backend cases + 22 browser E2E). Все 26 migrations применены в disposable PostgreSQL 17; fixture удаляет отдельную тестовую БД после прогона.
- `node --check frontend/app.js` и `git diff --check`: exit 0. Проверен 91 Markdown-файл и 1303 локальные ссылки: отсутствующих файлов нет. Регрессии существующих сценариев не обнаружены.
