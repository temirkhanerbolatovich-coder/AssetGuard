# Fleet test AssetGuard Agent

Цель: на 3–5 реальных Windows-PC доказать, что Agent переживает перезагрузку, потерю сети, остановку службы и перевыпуск credential без ручного редактирования реестра и не теряет историю инвентаризации.

## Правила пилота

- Для каждого PC создавать отдельный login/secret в разделе «Подключить Agent».
- Secret не записывать в протокол, таблицу, скриншот или чат.
- Все отчёты `test-assetguard-agent-readiness.ps1` сравнивать по `computer_name` и `agent_username`; login должен быть уникальным.
- На этапе pilot допустим неподписанный EXE только при ручной передаче ограниченной группе. Массовое распространение ждёт code-signing сертификат.

## Порядок для каждого PC

1. Записать модель PC, версию Windows и имя ответственного. Создать уникальный credential.
2. Сверить SHA-256 installer. Установить Agent от имени администратора и выполнить первую инвентаризацию.
3. Запустить:

   ```powershell
   .\test-assetguard-agent-readiness.ps1 -Phase INITIAL
   ```

   Отчёт должен завершиться `Passed=True`. В панели должны быть видны Agent `1.20`, installer version и статус `ONLINE`.
4. Перезагрузить Windows, дождаться запуска службы и запустить фазу `AFTER_REBOOT`. Сверить новое `windows_last_boot`.
5. Отключить сеть минимум на один цикл Agent. Не меняя конфигурацию, сохранить фазу `OFFLINE`, затем восстановить сеть. После нового `received_at` в панели сохранить `NETWORK_RESTORED`.
6. Остановить службу `glpi-agent`. Запустить её снова без изменения реестра и сохранить `SERVICE_RECOVERED`.
7. Отозвать credential в панели и убедиться, что новая отправка получает `401`. Создать новый credential и повторно запустить installer: ручное редактирование реестра не допускается. После отправки сохранить `REENROLLED`.
8. На обесточенном PC изменить RAM или диск, загрузить Windows и дождаться отправки. Сохранить `HARDWARE_CHANGED` и проверить, что инцидент ссылается на прежний endpoint/asset и показывает фактическую разницу.

## Критерий приёмки

Тест закрыт только когда:

- есть 3–5 полных наборов отчётов с уникальными `agent_username`;
- все фазы, где система должна быть здорова, имеют `passed=true`;
- после reboot, network restore, service recovery и re-enrolment появились новые immutable RawInventory и не изменился endpoint;
- ни на одном PC не пришлось вручную менять `HKLM\SOFTWARE\GLPI-Agent`;
- изменение RAM/диска дало один объяснимый инцидент без потери предыдущей истории.

Self-service re-enrolment после чистой переустановки Windows пока не входит в этот приёмочный цикл: для него нужен отдельный одноразовый protocol с admin approval.
