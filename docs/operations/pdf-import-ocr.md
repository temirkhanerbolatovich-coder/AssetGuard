# Импорт инвентаризационных PDF

> **Сверено 2026-10-06.** Текущий статус и границы проверки: [checklist](../product/current-project-checklist.md), [аудит](../quality/project-audit-2026-10-06.md). Датированные результаты отдельных этапов сохранены с исходными датами.

## Для пользователя

1. Откройте раздел **Имущество и компьютеры → Импорт и экспорт → Загрузить PDF**.
2. AssetGuard сначала показывает предварительный результат и ничего не сохраняет.
3. Просмотрите позиции по 25 строк на странице или найдите их по инвентарному номеру, названию и локации.
4. У каждой позиции проверьте организацию, номер, название, тип, количество, единицу, режим учёта, кабинет и действие: **Новая** или **Обновится**. Все пригодные строки включены по умолчанию; строки без подтверждённого количества исключены и требуют исправления в Excel; снимите флажок у лишней или неверно распознанной строки. Можно выделить/снять все строки текущей страницы.
5. Для скана сверьте проценты OCR с оригиналом. Это средняя уверенность движка по распознанным словам, а не вероятность правильной записи.
6. Нажмите **Импортировать выбранные** только после проверки. AssetGuard заново разбирает загруженный файл и применяет только оставшиеся выбранными строки. **Отмена** закрывает окно без записи.

По точному инвентарному номеру в той же организации запись будет обновлена; иначе будет создана новая. Если колонка организации отсутствует, named tenant ADMIN импортирует в свою организацию; глобальный bootstrap ADMIN использует `Default Organization`. Файл с явной чужой организацией отклоняется целиком с `403`, включая предпросмотр и исключённые строки.

Количество ведомости сохраняется в `quantity`, единица — в `unit`, режим — в `tracking_mode`; исходные бухгалтерские сведения остаются также в примечании. Стандартная ведомость создаёт одну `GROUPED`-позицию на строку. Например, 12 парт учитываются как 12 единиц одной позиции.

Excel и обычные PDF-таблицы принимают необязательные колонки `quantity`/«Количество», `unit`/«Единица измерения» и `tracking_mode`/«Режим учета». Режим — `INDIVIDUAL` или `GROUPED`; количество — целое от 1 до 1 000 000. Без режима количество больше 1 означает `GROUPED`. `INDIVIDUAL` допускает только 1. Запятая является десятичным разделителем: `1,000` означает 1, `12,000` — 12; дробное `1,500` отклоняется с `422`. Пробелы в числе допустимы. Старый файл без новых колонок сохраняет существующие количество/единицу/режим; для новой записи используются 1 / `шт.` / `INDIVIDUAL`. Excel export включает эти поля.

После акта перемещения или списания импорт сохраняет текущие количество, единицу, режим, статус и расположение обеих затронутых позиций. Предпросмотр показывает «сохранён остаток по акту» и исходное количество файла. Обновить учётные остатки через старую ведомость нельзя; название, тип и примечание могут обновляться. Основание решения — [ADR-006](../decisions/ADR-006-import-accounting-precedence.md).

OCR переносит количество только при распознанном полном числовом окончании стандартной строки. Если количество не распознано, новая позиция показывается с «Уточните в Excel», а применение возвращает `422`; снимите такую строку либо подготовьте исправленный Excel. У существующей позиции неизвестное количество сохраняет её текущий остаток. Процент OCR не заменяет сверку с оригиналом.

## Какие документы поддерживаются

- PDF с текстовым слоем, содержащий распознаваемые колонки реестра;
- типовая казахстанская инвентаризационная ведомость, где номер строки повторяется в начале и конце каждой позиции;
- скан такой ведомости, если OCR смог выделить отдельные строки, номер, название и границу учетных колонок.

Пустой бланк, итоговая сумма, подпись или строка вроде «оборудование всего» не являются отдельным активом и не импортируются. Если структура/качество документа не позволяют надежно выделить позиции, API возвращает ошибку предпросмотра и не записывает строки.

Ограничения: PDF не более 10 MiB; OCR — не более 30 страниц за один импорт. Для извлечения названию/номеру может потребоваться ручная правка исходной таблицы, если ведомость отличается от поддерживаемой формы.

## Локальная установка OCR

Tesseract OCR — свободный движок под [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0). Установка Windows-сборки не входит в Git и не обязательна, если сканы не импортируются. Варианты Windows установки описаны в [документации Tesseract](https://tesseract-ocr.github.io/tessdoc/Installation.html). Для локального сервера нужны бинарный файл Tesseract и языковые модели `rus`, `kaz`, `eng` из [официального набора tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd).

Укажите пути только в локальном `.env`:

```dotenv
ASSETGUARD_TESSERACT_CMD=C:\Program Files\Tesseract-OCR\tesseract.exe
ASSETGUARD_TESSDATA_DIR=C:\AssetGuard\tessdata
ASSETGUARD_OCR_TEMP_DIR=C:\AssetGuard\ocr-temp
```

Путь к `TESSDATA_DIR` должен быть ASCII-only и не содержать пробелов в Windows; временная папка должна быть ASCII-only и доступной на запись. Это нужно, чтобы Tesseract корректно открыл переданные ему файлы и языковые модели. Перезапустите API после изменения настроек. Проверка языков:

```powershell
tesseract --tessdata-dir C:\AssetGuard\tessdata --list-langs
```

Ожидаются `eng`, `kaz` и `rus`. В Linux production Docker image эти языки ставятся вместе с системным Tesseract; отдельные пути задавать не требуется. В текущей Windows-лаборатории был использован установленный Tesseract 5.4.0 и официальный набор `tessdata_fast` с commit `87416418657359cb625c412a48b6e1d6d41c29bd`. Исходные PDF, локальные модели, скриншоты и промежуточные изображения остаются в локальных/временных каталогах и не добавляются в репозиторий.

## Проверка и диагностика

- «OCR runtime не установлен» — укажите правильный `ASSETGUARD_TESSERACT_CMD`, установите `pypdfium2`/`pytesseract` и перезапустите API.
- «Языки не найдены» — проверьте `ASSETGUARD_TESSDATA_DIR` и вывод `--list-langs`.
- «Не найдена ведомость с построчными данными» — документ может быть пустым/сводным либо OCR не смог надежно разобрать отдельные позиции. Проверьте качество скана и текстовый слой; не применяйте такие данные как инвентарный реестр без ручной проверки.
- После выбора строк повторная отправка того же файла остаётся read-only до явного нажатия кнопки импорта.

Проверка API покрывает цифровые многостраничные ведомости, OCR-строки, исключение выбранной позиции и отклонение пустого бланка. Реальное распознавание пользовательских PDF следует перепроверять на каждом поддерживаемом формате документа: одинаковые цифры уверенности сами по себе не гарантируют одинаковую точность.

### Контрольный прогон на 2026-09-24

- `3333.pdf`: цифровая многостраничная ведомость, API вернул 211 позиций (211 новых, 0 обновлений); проверялся только предпросмотр, **импорт не применялся**.
- `66.pdf` и `9.pdf`: Tesseract действительно запускался с моделями `rus/kaz/eng`, но безопасный парсер не нашёл отдельных подтверждаемых строк. API вернул 422, ни одна запись не добавлена. Это ожидаемо для сводной/пустой формы: её нельзя выдавать за построчный школьный инвентарь.
- `GET /health` и `/health/ready` после локальной миграции отвечали штатно; версия схемы — `0021_vision_location_scope`.
