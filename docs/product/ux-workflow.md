## Пользователи и рабочие сущности

Администратор школы ведёт структуру/реестр, imports, сотрудников и Agent. Ответственный за инвентаризацию работает в назначенных кабинетах. IT-специалист проверяет компьютеры, связь и изменения железа. Эти функции опираются на существующие роли и grants; отдельные platform/school роли ещё не выделены.

**Имущество** — запись учёта, **компьютер** — ManagedEndpoint технического отчёта, **Agent** — установленный collector/delivery runtime. Мебель не получает статус компьютера без связи. Обнаруженный Agent до связи с Asset имеет отдельную карточку.

## Вход и навигация

1. До входа показывается самостоятельная форма; приватные `/admin` запросы не выполняются.
2. Named login проверяется через `/auth/me`. Bootstrap key — отдельный вход для настройки.
3. Четыре ежедневных раздела: обзор, имущество, инциденты, кабинеты. Только ADMIN открывает администрирование.
4. В администрировании четыре task tabs: компьютеры, подключение Agent, восстановление, Telegram. Сотрудники, обмен данными и справка доступны отдельными переходами.
5. Back/Forward, прямые hash-ссылки и refresh восстанавливают допустимый экран. Выход очищает закрытые данные, формы, media URLs и session drafts; запрашивается server session revoke.

## Настройка школы

1. ADMIN работает в уже назначенной организации; отдельного UI/API создания школы нет. Список организаций scoped. Новый tenant onboarding требует отдельного решения.
2. Создаёт корпус, этаж и кабинеты, назначает ответственного.
3. Добавляет имущество либо открывает Excel/PDF preview: scope, source row/page, create/update, quantity/unit и room. Строки исправляются в исходном файле или исключаются; сохранение явно подтверждается.
4. Создаёт отдельный Agent credential и передаёт его installer на нужном PC. Связывает обнаруженный endpoint только с соответствующим individual IT Asset.
5. Проверяет snapshot и явно принимает baseline. Назначает сотрудникам роли и VIEWER/EDITOR grants на локации.

## Ежедневная работа

Обзор показывает четыре показателя, приоритетные задачи и последние события. Завершённый onboarding скрывается; technical operations доступны ниже основного контекста. Статусы Agent и учётное состояние имущества различаются.

В реестре пользователь совместно применяет поиск, фильтры и сортировку, открывает карточку и возвращается к выбранной странице/позиции в текущей сессии. DOM показывает до 20 строк; сервер пока отдаёт assets/endpoints целиком. Добавление — основное действие, import/export находятся в «Ещё» и администрировании.

Центр инцидентов объединяет hardware и physical findings. Карточка показывает исходную проверку/evidence, время, сравнение и доступное решение. Missing value не превращается в zero; неизвестный объём RAM не объявляется уменьшением. Решение записывается в историю и не меняет baseline автоматически.

## Кабинет и обход

Карточка кабинета имеет шесть вкладок: обзор, проверки, имущество, обход, инциденты, история. «Проверки» объединяют Agent/baseline и экспериментальное фото. «Начать обход» — главное действие; QR, редактирование и фото доступны через «Ещё».

QR кабинета открывает `#room-audit=UUID` и после входа запускает обход. Оператор явно отмечает каждую текущую позицию; QR individual имущества с количеством 1 может отметить «На месте», grouped позиция требует ручной сверки количества. BarcodeDetector/camera зависит от браузера; ручной ввод доступен всегда.

Черновик в `sessionStorage` восстанавливается в той же сессии пользователя/кабинета. Перед записью показывается итог; одним POST сохраняются акт, история, физические инциденты и outbox. Сетевой lost response требует сначала проверить историю, поскольку API обхода не имеет idempotency key.

ADMIN/EDITOR принимает physical decision. Перемещение требует целевого кабинета, количества и номера акта; partial grouped MOVE — нового inventory number. WRITE_OFF уменьшает остаток или закрывает позицию. Source/destination grants проверяются API. Итоговая операция имеет PDF-акт.

## Ошибки, безопасность и доступ

Пустой реестр, пустой фильтр, отсутствие grants, недоступная сеть и ошибка загрузки имеют разные пояснения и действия. Forms сохраняют ввод после подтверждённого отказа; double-submit блокируется. Поздние ответы старого route/сессии игнорируются. Ключ Agent показывается один раз и очищается после закрытия/выхода; очередь Telegram получает только безопасные metadata.

Named ADMIN ограничен организацией. VIEWER, LOCATION_MANAGER, INVENTORY_CLERK допускаются к Viewer-level routes; фактические чтение/запись определяются tenant и VIEWER/EDITOR grants. Роль VIEWER сама по себе не гарантирует запрет записи при выданном EDITOR grant. Hardware baseline/technical decisions и users/credentials/imports остаются ADMIN-only. [64-operation matrix](../security/admin-route-access-matrix.md).

## Приёмка и открытая работа

Автоматические Chromium scenarios, contrast/focus, keyboard/reflow/reduced motion и настоящий zoom 200% проходят; полный набор — 145 cases. Требуются Firefox/Safari, NVDA/VoiceOver, zoom 400%, реальные телефоны, representative performance и 3–5 сотрудников школы. Цель usability: ≥90% применимых задач без помощи, без опасных ошибок.
