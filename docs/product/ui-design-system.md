# AssetGuard — UI design system

## Назначение

AssetGuard — рабочий инструмент сотрудника школы, а не презентационный
dashboard. Интерфейс должен помогать принять следующее действие: понять
состояние, найти объект, проверить расхождение и зафиксировать решение.

## Принципы

1. **Смысл раньше декора.** Каждый цвет, бейдж и кнопка сообщает состояние
   либо следующее действие. Декоративные градиенты, случайные иллюстрации и
   «пустые» карточки не используются.
2. **Одна визуальная иерархия.** Заголовок страницы, краткое объяснение,
   ключевые показатели и рабочее содержимое идут в одном предсказуемом порядке.
3. **Спокойный контраст.** Тёмная навигация отделяет рабочую область; основной
   акцент — насыщенный teal. Красный, янтарный и зелёный зарезервированы только
   для опасности, внимания и подтверждённой нормы.
4. **Ясные действия.** У каждого блока — один главный action. Уточняющие и
   потенциально опасные действия получают secondary/quiet стиль или диалог
   подтверждения.
5. **Доступность по умолчанию.** Контраст текста и контролов достаточен для
   обычного рабочего освещения; фокус видим; нативные controls сохраняют
   семантику; иконки всегда дополняются текстовой подписью.

## Токены

| Роль | Токен | Применение |
| --- | --- | --- |
| Рабочий фон | `--canvas` | фон содержимого |
| Поверхность | `--surface` | панели, формы, таблицы |
| Текст | `--ink`, `--navy` | основной текст и заголовки |
| Действие | `--accent` | primary controls и active navigation |
| Норма | `--good` | подтверждённое корректное состояние |
| Внимание | `--warn` | требующая проверки информация |
| Ошибка | `--danger` | ошибка и критичное расхождение |

## Компоненты

- **Sidebar:** бренд, понятные группы навигации и состояние сессии. SVG-иконки
  используются как подсказка, но не являются единственным носителем смысла.
- **Panel:** единый контейнер с 12 px радиусом, тонкой границей и мягкой тенью.
- **Metric card:** кликабельна только если ведёт к конкретному отфильтрованному
  результату; показывает число, название и краткое объяснение.
- **Status pill:** короткое состояние, а не место для длинного текста.
- **Dialog:** один фокусный сценарий, явная отмена, Escape и восстановление
  фокуса после закрытия.

## Инженерные правила

- Не вводить новый цвет или радиус без роли в токенах.
- Не заменять нативные form controls имитациями без необходимости.
- Не добавлять обработчик, который меняет данные, без disabled/loading/error
  состояния и browser E2E либо integration-покрытия.
- Держать UI-компоненты небольшими и с одной ответственностью: отображение,
  маршрутизация и API-действие не смешиваются без необходимости.
- Новые визуальные изменения проверять на desktop и ширине 360–390 px.
