# Модель инвентаризации AssetGuard

## Два режима учёта

| Режим | Для чего | Единица учёта | Контроль |
| --- | --- | --- | --- |
| Индивидуальный | ПК, ноутбуки, принтеры, проекторы, сетевое оборудование | Один актив с инвентарным номером и QR | Agent, состав железа, baseline, инциденты |
| Групповой | Парты, стулья, мячи, лабораторные наборы и прочее имущество | Одна номенклатурная позиция с количеством и единицей измерения | Физическая сверка и QR кабинета |

Agent может быть привязан только к индивидуальному IT-активу. Групповая запись не маскируется под компьютер и не получает ложных технических инцидентов.

## Рабочий процесс школы

1. Администратор создаёт структуру: организация → корпус → этаж → кабинет и назначает ответственного за кабинет.
2. Первичный реестр загружается из Excel/PDF. Каждая строка получает категорию, режим учёта и локацию.
3. IT-активы связываются с Agent. После первой полной инвентаризации принимается baseline.
4. При обходе ответственный открывает QR кабинета, сверяет групповые позиции и фиксирует фактическое количество.
5. Расхождения становятся задачами: недостача, излишек, перемещение или списание. Решение сохраняется в истории.
6. Руководитель получает отчёты по корпусу, этажу, кабинету, категории и ответственному.

## Роли и доступ

| Роль | Область | Возможности |
| --- | --- | --- |
| Администратор организации | Вся организация | Структура, пользователи, Agent, все операции |
| Менеджер локации | Назначенный корпус/этаж/кабинет | Реестр своей области, перемещения, сверки |
| Ответственный за кабинет | Назначенный кабинет | Просмотр, сверка группового имущества, заявки на расхождения |
| Наблюдатель | Назначенная область | Только просмотр и отчёты |

Следующий технический этап: таблица назначений пользователя на корпус/этаж/кабинет и обязательная фильтрация всех API по этим назначениям.
