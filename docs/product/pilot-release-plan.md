# План пилотного релиза до Idea Battle

## Цель

К 25 сентября подготовить работающий локальный и временно публичный контур, в котором оператор ведёт реестр по локациям, открывает карточку через QR, импортирует реестр из Excel, получает Agent-инвентаризацию и разбирает объяснимый Incident.

## Реализуется в репозитории

- Локация Asset: организация → корпус → этаж → кабинет.
- QR-код для каждой карточки: адрес берётся из `ASSETGUARD_PUBLIC_URL`.
- Excel import/export реестра: создание и обновление активов по паре организация + инвентарный номер; import всегда сначала показывает количество изменений. Поддерживаются технические и распространённые русские заголовки: «Инвентарный номер», «Наименование», «Тип оборудования», «Корпус», «Этаж», «Кабинет».
- Vision-скан можно связать с конкретным Asset и открыть его карточку прямо из результата анализа.
- Agent умеет по явному параметру `NetworkTarget` добавлять четыре ICMP-пробы: доступность, packet loss и среднюю задержку; скорость канала и содержимое трафика намеренно не собираются.
- `install-pilot-agent-schedule.ps1` регистрирует безопасное расписание на каждом pilot-PC и не встраивает секрет в задачу Windows.

## Внешние зависимости

| Задача | Что нужно от команды |
| --- | --- |
| Публичный показ | Запустить Cloudflare Quick Tunnel с компьютера презентации. |
| Постоянный production | VPS или сервер, домен/DNS и доступ к ним. |
| Пилот нескольких PC | Установить GLPI Agent и запустить подготовленный скрипт на каждом устройстве. |
| Recovery rehearsal | Выбрать off-site носитель или облачное хранилище. |

## Критерий готовности к 25 сентября

1. На Dashboard остаются реальные устройства и демонстрационный Incident.
2. QR открывает карточку на телефоне через временный HTTPS URL.
3. Тестовый Excel-файл можно выгрузить, изменить локацию и импортировать обратно.
4. Agent отправляет минимум одну новую инвентаризацию во время репетиции, включая сетевую метрику, если указан `NetworkTarget`.
5. Vision baseline и warning воспроизводятся на двух demo-фотографиях.
