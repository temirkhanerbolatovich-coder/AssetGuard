# AssetGuard: редизайн Ledger, 2026-10-05

## Направление и границы

Ledger — спокойный рабочий реестр: светлый фон, чернильный текст, синий акцент,
тонкие разделители и типографика, которая помогает сравнивать записи.
Первый уровень отвечает на вопросы «что это», «где», «что требует внимания»
и «что можно сделать». Оборудование, доказательства и подробная история
открываются в карточке.

Сохранены FastAPI, PostgreSQL и vanilla HTML/CSS/JavaScript, hash-ссылки QR и
Telegram, существующие права, API, физические операции, импорт, экспорт,
Agent и Vision. Новых серверных endpoints, миграций и JS-зависимостей нет.
Карточка обнаруженного компьютера использует уже существующие защищённые
GET endpoints. Vision получает общие стили; модель и обработка фотографий
не менялись.

## Аудит перед изменениями

Проверены оболочка, все девять основных разделов, карточки имущества,
кабинета и инцидента, диалоги, обработчики форм, API-авторизация и browser E2E.

| Проблема | Решение |
| --- | --- |
| Inter указан в CSS, но файлы не загружаются; обычная Windows использует fallback | Локальный Golos Text, настоящие переменные начертания, проверка фактически отрисованной гарнитуры через Chromium CSS API |
| Несколько перекрывающих визуальных слоёв, 11–12 px, веса 650/750/800 | Удалена старая типографика и оформление; общие токены и одна система компонентов |
| Название страницы повторяется в глобальном и локальном заголовке | Один заголовок страницы; рядом с рабочим списком — результат и действия |
| Большой повторный блок последнего инцидента и технический pipeline в обзоре | Один компактный список задач; доказательства на странице инцидента |
| Завершённый onboarding постоянно занимает экран | Автоматически скрывается после двух обязательных шагов; «Быстрый старт» открывает его снова |
| Характеристики CPU/RAM находятся в последней проверке | В реестре только время/способ проверки; состав оборудования — в карточке |
| «Не связано» находится в количестве | Количество группы рядом с типом; связь имеет отдельный столбец и представление |
| Большая кнопка открытия в каждой строке | Доступная ссылка в названии, независимое действие связи |
| У обнаруженного компьютера нельзя изучить карточку до связи | Новый UI route `#computer=<uuid>` поверх существующего API |
| Повторная отправка добавления/связи и ошибки только в toast | Блокировка submit, процесс, ошибка в форме, сохранение введённых значений |
| Сравнение RAM соединяет характеристики через точки | Таблица по полям; отдельные обозначения отсутствующих сведений и неопределённого объёма |

документам. Awwwards возвращал timeout/error для запрошенных страниц;
награды этих сайтов не заявляются. Linear, Geist, Superlist и Pentagram

Это самостоятельная система AssetGuard. Скопированные layout, библиотеки или
графические материалы внешних сайтов в приложение не включены.

## Карта данных и прав

| Сведения | Источник | Где видны |
| --- | --- | --- |
| Название, номер, тип, количество, кабинет, примечание | Запись имущества; сотрудник или импорт | Реестр, основные сведения |
| Имя компьютера, последний контакт, снимок, аппаратные идентификаторы | GLPI Agent → raw inventory → snapshot | Связь, проверка, карточка компьютера, оборудование |
| Эталон | Явное подтверждение разрешённым оператором | «Эталон и изменения» |
| Технические инциденты | Сравнение с эталоном | Обзор задач, центр и карточка инцидента |
| Физические инциденты и акты | Обход и разрешённое решение | Кабинет, центр инцидентов |

ADMIN управляет пользователями/Agent, импортом/экспортом и связью компьютера.
LOCATION_MANAGER и INVENTORY_CLERK редактируют разрешённые кабинеты согласно
существующим grants. VIEWER читает доступные записи. Сервер повторно проверяет
организацию и кабинет, включая прямые ссылки. Редизайн не расширяет права.
Bootstrap administrator видит «Все организации»; реальные названия, включая
`Default Organization`, сохраняются в данных и подробностях.

## Сценарии и компоненты

- Девять основных routes: обзор, имущество, инциденты, кабинеты, импорт/экспорт,
  доступ, Agent, инструкция Agent и проверка по фото. Desktop sidebar можно
  свернуть; ссылки имеют понятные названия и native tooltip. Mobile сохраняет
  тот же набор разрешённых задач.
- Реестр: все записи / имущество / компьютеры / без связи, поиск, фильтры,
  сортировка, пагинация. Поиск, условия, представление и страница сохраняются
  при переходе в карточку и обратно в течение текущей сессии.
- `#asset=<uuid>&tab=<tab>`: основные сведения, оборудование, эталон/изменения,
  инциденты, история, технические данные; неприменимые разделы скрываются.
- `#computer=<uuid>`: полученный состав, последнее сообщение, связь, инциденты,
  раскрываемые идентификаторы и история. Отдельные GET читаются только при
  открытии; используются существующие кэш и дедупликация запросов.
- Добавление и редактирование имущества — нативные dialog в виде боковой панели.
  Остальные диалоги сохраняют собственные фокусные сценарии.
- Идентификаторы длиной от 24 символов имеют копирование с подтверждением.
  Ошибка Clipboard API предлагает выделить значение и скопировать вручную.

## Сравнение без ложных выводов

RAM сравнивается по объёму, типу, частоте, слоту, производителю, серийному номеру
и модели. Storage и CPU используют собственные поля. Поля, отсутствующие в
обоих снимках, не создают пустые строки. Значение в новом снимке подсвечивается
только при отличии; цвет дополнен текстом и заголовками «Было / Стало».

`numslots` нормализуется сервером в `slot`: это обозначение слота, а не количество
модулей. Значение `0` сохраняется и показывается как слот 0. Нулевые объём и
частота показываются как «Не указан / Не указана», а не как доказанная физическая
пропажа. `null` стороны сравнения означает отсутствие компонента **в снимке**.
UI предлагает проверить полный отчёт и компьютер. Изменившееся описание само
по себе не подтверждает замену. Сырые evidence и серверная классификация
не переписываются.

## Шрифты, движение и производительность

Golos Text self-hosted WOFF2: кириллица, расширенная кириллица и Latin, всего
77 456 байт; лицензия SIL OFL хранится в `frontend/fonts/OFL.txt`. Основные
кириллический и Latin subsets preload, расширенный подгружается по символам.
`font-weight: 400 700`, `font-synthesis: none`; основной текст 400, названия и
действия 500, заголовки 600. Числа используют `tabular-nums`. CSS не запрашивает
Google Fonts во время работы приложения.

Общие длительности: controls 150 ms, меню/раскрытия 200 ms, dialog/drawer
260 ms. Панели, вкладки и toast используют opacity/transform с перемещением
4–12 px. Hover и pressed отличаются без сильных теней. Skeleton использует
пульсацию opacity. `prefers-reduced-motion: reduce` отключает движение и плавный
scroll во всех компонентах. Непрерывных декоративных эффектов нет.

Реестр отрисовывает максимум 20 строк; новых запросов при фильтрации нет.
Средние ширины используют локальную прокрутку таблицы, телефон — карточки строк.
Страница целиком не должна прокручиваться горизонтально.

## Проверка и ограничения

Запуск из `backend`:

```powershell
$env:ASSETGUARD_RUN_BROWSER_E2E='1'
$env:ASSETGUARD_REDESIGN_PREVIEW_DIR='C:\AssetGuardChecks\redesign'
.\.venv\Scripts\python.exe -m pytest tests -q
```

Набор использует временную PostgreSQL БД. Новые E2E проверяют реальные записи,
ошибку и повторное сохранение, защиту от повторного submit, связь, карточку
компьютера с полученным снимком, отказ чтения и retry, onboarding, источники,
кириллический custom font, шесть размеров и оба режима motion. Существующий
набор проверяет импорт/экспорт, обход/акты, разрешённое решение инцидента,
четыре роли и tenant boundary, контраст, фокус и диалоги, реестр 216/1000 записей.
Тест 200% использует `chrome.tabs.setZoom` в отдельном временном браузере:
Chrome возвращает zoom 2, `innerWidth=720` при viewport 1440, DPR 2. CSS zoom
и pinch emulation не используются. Расширение существует только в тесте.

Не заявляется полная WCAG-сертификация или приёмка оператором школы. Safari,
Firefox, NVDA и репрезентативная медленная сеть требуют самостоятельной
ручной проверки. Для ручного имущества в list API нет времени последнего
физического обхода — показывается способ проверки; история доступна в кабинете.
Все списки пока загружаются сервером целиком; 1000 записей — лабораторная
проверка ограниченной отрисовки, а не multi-school capacity acceptance.

Итоговая приёмка и снимки: [отчёт](../../outputs/assetguard-redesign-2026-10-05/report.md).


## Совместимость объёмов памяти

RAM уже допускает MiB от Agent и байты старого JSON transport; UI применяет
существующую границу 1 048 576 также при чтении snapshot карточки компьютера.
Для видеопамяти используется то же правило представления: 4096 MiB и
4294967296 байт отображаются как 4 ГБ, нулевой/отсутствующий объём не выдается
за отсутствие видеокарты. [Исходный Win32 collector GLPI](https://github.com/glpi-project/glpi-agent/blob/develop/lib/GLPI/Agent/Task/Inventory/Win32/Videos.pm)
переводит AdapterRAM в MiB; byte-вариант подтверждён старой JSON fixture
проекта. Это совместимость существующих источников, не изменение evidence.
