# Первый этап UI/UX: вход и каркас приложения

Дата: 2026-10-05. Требования: UX-01/02/03 и относящаяся к входу часть UX-13 из [ТЗ UI/UX](../product/ui-ux-modernization-spec.md).

## Поведение

До входа показывается отдельный адаптивный экран с логином и паролем. Реестр, меню и placeholders закрытых данных скрыты; запросы к `/admin/*` не выполняются. Вход по bootstrap key выбирается отдельной кнопкой и не смешивается с паролем сотрудника.

При именованном входе вызывается `/auth/login`; любой полученный credential затем проверяется `/auth/me`. Только подтверждённая учётная запись открывает каркас приложения. Сохранённый session token не вставляется в поле пароля. Прямые hash-ссылки Asset/Room/Incident сохраняются при входе и восстановлении сессии.

Каркас показывает пользователя, роль и область работы. Для scoped ADMIN отображается название разрешённой организации из существующего admin API. Для остальных scoped ролей без этого admin-only запроса показано «Назначенная организация»; для legacy global администратора — «Область администратора платформы». Новых прав и публичных API не добавлено.

У основной загрузки явные состояния loading/ready/error. Ошибка не выдаётся за успешный вход или актуальные данные; повторная загрузка восстанавливает текущий route. Чтение JSON API и login/logout ограничены 20 секундами. Длительные записи, включая анализ Vision, сохраняют прежнее поведение. У media Blob остаётся прежний timeout contract; добавлена проверка смены сессии перед использованием результата.

401 завершает локальную сессию и возвращает вход с пояснением. 403, 404, rate limit, временная ошибка сервера, отсутствие сети и timeout получают понятные сообщения. Выход очищает token, runtime state, route caches, созданные media URLs, значения секретов, формы и основные динамические области. Для именованной сессии запрашивается серверный revoke; при неподтверждённом отзыве показывается отдельное сообщение.

Ответы старой загрузки/сессии не восстанавливают закрытый интерфейс. Карточки актива, кабинета и инцидента используют поколение текущего view: ответ после смены раздела игнорируется. При загрузке актива/инцидента старые подробности скрыты до получения нового результата.

## Доступность и вид

Системный шрифт, navy/teal, отдельная карточка входа, labels, явный переключатель видимости пароля. Ошибка входа получает focus и ссылку к полю. Есть переход к содержимому, видимый focus; мобильное меню закрывается по выбору раздела, Escape или нажатию вне меню. Escape возвращает focus кнопке меню. Имя сотрудника видно на телефоне. Не меняются Vision backend/model/inference/storage, роли, baseline и Telegram worker.

Проверяются ширины 320/360/390/768/1024/1366/1920 px до и после входа. Это подтверждение тестируемого каркаса, а не полный аудит WCAG или usability всех экранов. Остальные формы, таблицы, единый центр физических/технических инцидентов и полный accessibility/performance audit остаются следующими этапами.

## Проверка

Из `backend`:

```powershell
$env:ASSETGUARD_RUN_BROWSER_E2E='1'
.\.venv\Scripts\python.exe -m pytest -q tests/unit tests/integration tests/e2e
```

Дополнительные browser scenarios: anonymous/no private requests, named login и неверный пароль, восстановление/прямые ссылки, 403/503/retry, expired session, server revoke, logout during loading, delayed asset response, timeout через [Playwright Clock](https://playwright.dev/python/docs/clock), Enter/Escape/focus и mobile overflow.

Для обновления preview только на синтетических локальных данных добавьте `ASSETGUARD_CAPTURE_UI_PREVIEWS=1`. Обычный запуск не перезаписывает PNG.
